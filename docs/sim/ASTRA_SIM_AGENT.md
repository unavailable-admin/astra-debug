# Astra → EASIM Scene11

本工作区的接入入口是 `astra_sim_agent.py`。模型通过官方 OpenAI Chat Completions 读取
机器人状态（可选相机图像），输出 JSON 动作，客户端校验后通过 WebSocket 执行，再把新观测返回给模型。
这是一份实验客户端，拼字成功与否须查看实际录像；模型的成功声明不会自动算作通过。

新增自动闭环原型：`closed_loop_spell.py`，移除了人工检查文件和保存计划的依赖，
通过 API 判断当前场景与抬起结果。运行方法、验证状态和限制见
[CLOSED_LOOP_SPELL.md](CLOSED_LOOP_SPELL.md)；旧抓放录像不能视为新自动流程的成功记录。

最新结果：已完成 **I 的完整抓取、低空搬运、放下和撤手**，最终桌面可读出 HI。
录像：`runs/grasp_20260910_093325/preview.mp4`；最终画面：`runs/hi_grasp_final.jpg`。
便于查看的压缩录像：`runs/grasp_pick_place.mp4`。按仿真 30 Hz 回放约 63 秒，
不包含等待和视觉检查暂停的墙钟时间；原始逐帧图像保留在 run 目录。
这是多轮调试后的场景结果，H 来自先前尝试且有平面内转角；不能描述为模型一次
无人干预完成了两个字母的抓放，也尚未验证多次运行的成功率。

## 运行

2026-09-10 实测新服务器：`ws://10.19.4.253:8080`–`:8083`。
客户端默认使用 8083，仅接入空闲的 `showroom_scene_11`；不要与其他任务共用端口。
SSH 的 2222 端口与仿真 WebSocket 端口不同，运行客户端不需要 SSH 登录。

```bash
PY=/kairos_vepfs_volc/embodied/fuzuoyi/anaconda3/envs/kairos_3_1_pre/bin/python
"$PY" probe_astra_sim.py --uri ws://10.19.4.253:8083
"$PY" astra_sim_agent.py --uri ws://10.19.4.253:8083 --word ACE --rounds 24 --track-letters
```

Python 依赖：NumPy、SciPy、Pillow、websockets >= 15；字母跟踪另需 OpenCV。
密钥从 `.secrets/openai_api_key` 读取，不记录在日志或命令行中。
官方 `https://api.openai.com/v1` 使用 `http://127.0.0.1:18888` 代理；内网 WebSocket 直连，
不继承公网代理环境变量。执行公网安装前，仍应遵守仓库的代理探测要求。

## 控制方式

- `move_joints`：具名关节绝对角，未指定关节保持当前观测角。检查 USD 关节限位，
  单次变化最多 0.35 rad，插值每帧最多 0.015 rad，然后等待动作后反馈。
- `move_wrist`：世界坐标中的腕部 XYZ 和可选 wxyz 四元数。位置变化最多 0.18 m，
  逆运动学后仍受关节变化限制；一次目标最多执行 12 段反馈控制，停滞时返回实际误差。
- `finish`：停止尝试并记录模型判断。`success_verified` 不因模型声明而置为 true。

所有坐标均为世界坐标米制：+X 向机器人右侧，+Y 向桌面远侧，+Z 向上。
EEF 是 `wrist_yaw_link` 的原点，不是指尖或抓取中心。
Scene11 的 `arm26` 只控制 MCP/CMC；DIP/IP 保持初始设定。
没有碰撞规划器或已训练的抓取策略，具体抓取与摆放仍需实际验证。

客户端启动时重新比对；误差超过 0.005 m 时不开始模型控制。

重新导出才需要 `usd-core`（本地已安装在 `.sim_deps`）：

## 网关与记录

测试中，Responses 路径的简单文本与小图像请求可成功，但多次机器人动作请求
返回 HTTP 502 / `upstream_error`。同一模型切到 `/v1/chat/completions` 后，
最小抬腕坐标请求约 4.6 秒返回正确结果。当前 agent 使用该 Chat 路径、低推理强度和 JSON 文本命令。
默认发送精简的当前状态和最近两条命令；`--vision` 才直接发送 640×360 图像给模型。
`--track-letters` 使用客户端的青色字母模板跟踪与桌面平面标定，向模型提供数值位置；
这不是模型直接看图，也不是仿真真值。对遮挡、翻倒与低置信度匹配返回未知。
日志中的 `command_transport=validated_json_text` 明确标注该模式；
包装成内部命令的 `function_call` 记录不是网关返回的原生工具调用。

`runs/astra_<时间>/` 保存初始 status、订阅回执、每帧 JPG/状态、模型原始响应与报告。
`actions_sent` 表示服务端确认接收的动作帧数；实际执行须结合帧内 `executed_actions`
及腕部位姿变化判断。场景内没有自动拼词判定器，必须检查最终字母位置与图像。

执行端的确定性校验见 `runs/sim_motion_validation/report.json`：52 帧动作完成右腕
抬高 3 cm 并回位，实测上移 2.968 cm，目标误差约 0.325 mm，回位误差约 0.330 mm。
这是客户端的控制校验，**不是**模型自主完成拼字的记录。

## 抓取试验

`grasp_letter_demo.py` 在 8081 上测试拇指 / 食指夹持 H 或 I，再搬到前排。
当前使用 3.5 cm 低空搬运；早期版本曾抬高 8 cm。
该实例已通过 `switch_action_layout` 切换为 `full36`。这是控制器验证，
不应计为新增的 Astra 自主控制记录。

实测注意：36 维输入并不意味着当前手资产的每个指节都能独立运动。空中预抓测试中，
食指 DIP 约为 MCP 的 0.89 倍，拇指 IP 约为 CMC pitch 的 2.29 倍；
这与资产内的 mimic gearing 一致。直接发送彼此矛盾的独立目标无法收敛。
抓取脚本使用符合联动比例的角度，并在移动腕部时持续保持夹指闭合目标。

脚本抬手后写入 `checkpoint.json` 并暂停，需要本地视觉核验后在该 run 目录写入
`continue.json`（`{"grasp_verified": true}` 才允许搬运；false 会下降、张手并撤回）。
文件是实验控制接口，不是用户必须手动操作的批准流程。抬手动作完成不能自动证明
物体离桌，必须核对实际图像；超时也不会默认为抓取成功。

抓取实测结果：`runs/grasp_20260910_090630/` 中，H 在闭合后随手上移，
经第 920、1000、1052 帧连续视觉核验，确认 H 保持夹在两指之间，字母面朝上。
随后搬运过程中 H 继续随手移动，但腕部 IK 在接近前排时返回 17.1 mm 的不可达
位置误差，控制器停止，**未完成受控放下**。该次 `grasp_success_verified=true`
仅表示夹起已确认，不表示完整抓放或拼字通过。录像在同目录 `preview.mp4`。
腕部上移目标为 8 cm；物体的独立三维高度没有仿真真值测量。

后续路径优化：固定 90° 抓取朝向、高举搬到前排时，实测肘关节和腕 yaw 同时达到
下限。空中转向虽可绕开限位，却在 `runs/grasp_20260910_092505/` 中导致 H 滑脱，
已保留失败判定。因此当前脚本只在空手接近 / 撤回时转向，夹住后保持 90°，
将夹持中心从 z=0.792 抬至 0.827，沿前方空位直线搬运，再下降松手。
接触前检查关键姿态的 IK 位置及方向残差；这不是完整碰撞规划。
贴近桌面张手时若指尖受桌面阻挡，不能要求其先达到全部空中角度；当前松手过程
先发送张开目标，再上撤 12 mm 完成张手。是否放置成功仍须核验方块和手分离后的画面。

优化后的实测：`runs/grasp_20260910_093325/` 共执行 1881 帧动作，无运行错误，
第 1204 帧确认 I 随手抬起，第 1518 帧记录松手，第 1881 帧确认手已撤开、I
直立留在前排。H/I 最终位置经视觉确认字母身份、青色连通域中心和 11 个参考字母
的平面标定估计，分别距模型目标约 7.2 / 6.4 mm；该估计有数毫米不确定性。
原字母模板在最终透视下漏检，所以最终身份经本次会话的视觉核验，不能把新增样本的
自匹配分数当成独立识别置信度。详情在 `visual_verification.json`。

```bash
"$PY" grasp_letter_demo.py --letter I
```

此命令使用保存的真实 Astra 计划，包含本地视觉检查暂停，且会操作当前场景；
不自动恢复字母原位置。8081 当前保持 full36，其他实例的布局未随之切换。
